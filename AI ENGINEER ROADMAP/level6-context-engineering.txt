Level 6 · Context Engineering

Scope: manage the model’s limited context window deliberately — decide what enters, what stays, what gets compressed, and what gets moved outside — and build the agent harness that applies these decisions across long-running work.

M6.1 · The context window as a resource — (sessions: 1)

Treat context as a limited budget rather than “more is always better.”
Understand context rot, distraction, conflicting context, lost-in-the-middle, and token/cost growth.
Inspect what actually enters the model’s window and identify which parts are useful versus noise.
Allocate rough budgets across instructions, conversation history, retrieval, memory, tools, and working state.
Outcome: Diagnose when model degradation is really a context-management problem.

M6.2 · Context selection & assembly — (sessions: 2)

Assemble instructions + conversation history + retrieved knowledge + memory + tool definitions/results + application state deliberately.
Decide what should be always present, dynamically retrieved, summarized, or excluded.
Prioritize information based on relevance, importance, recency, and reliability.
Order and structure context so instructions, evidence, memory, and user data remain clearly distinguishable.
Avoid redundant, stale, contradictory, or irrelevant context.
Outcome: Construct the smallest useful context for the current model decision.

M6.3 · Compression & compaction — (sessions: 2)

Summarize growing conversation history while preserving goals, constraints, decisions, and unresolved work.
Compact large tool outputs before feeding them back into the model.
Apply rolling summaries and hierarchical summarization for long-running tasks.
Preserve exact structured information separately when summarization could lose important details.
Understand the trade-off between context reduction and information loss.
Outcome: Reduce context size without losing task-critical information.

M6.4 · Memory & state offloading — (sessions: 2)

Move information outside the active window using scratchpads, files, databases, memory stores, task state, and working notes.
Distinguish active context from information that can be stored externally and retrieved later.
Persist plans, completed steps, decisions, intermediate results, and important facts across long-running tasks.
Build note-taking agents that write useful information externally and recall it when required.
Understand the distinction between memory for remembering and offloading for freeing context space.
Outcome: Build systems that do not require the entire task history to remain inside the model’s context.

M6.5 · Long-context strategies — (sessions: 1)

Understand why large context windows do not eliminate context-engineering problems.
Manage lost-in-the-middle using better positioning, selective retrieval, and context restructuring.
Compare full-context stuffing, retrieval-over-history, summarization, hierarchical context, and selective loading.
Decide when to give the model more context versus retrieve only the relevant parts.
Outcome: Choose an appropriate strategy for very long documents, conversations, and agent runs.

M6.6 · Tool context management — (sessions: 1)

Understand that tool definitions and tool results also compete for context-window space.
Dynamically expose only the tools relevant to the current task where possible.
Summarize or filter large API/search/database outputs before returning them to the model.
Keep full tool results externally and retrieve details again when required.
Prevent long agent loops from accumulating unnecessary observations and tool output.
Outcome: Keep tool-heavy agents coherent without letting their action history overwhelm the context.

M6.7 · Context caching & efficiency — (sessions: 1)

Understand how repeatedly sending large static contexts affects cost and latency.
Structure stable instructions and reusable context to benefit from prompt/context caching where supported.
Separate stable context from rapidly changing task state.
Reduce redundant tokens while preserving useful information.
Measure token usage, cache utilization, latency, and cost rather than optimizing blindly.
Outcome: Make large-context applications more efficient without sacrificing quality.

M6.8 · Harness engineering — (sessions: 2)

Session 1 · The agent harness
Understand the harness as everything around the model that turns it into a working agent: the loop, system prompt, tool set, context management, state, permissions, and the environment it acts in.
Recognize that the same model can succeed or fail on the same task depending on its harness, and that many agent failures are harness problems rather than model problems.
Design the agent loop: how model calls and tool calls alternate, how results and errors are fed back, and when to stop using step, time, and token limits.
Decide what the harness enforces versus what the model decides: fixed workflow steps, permission checks, human approval for risky actions, and safe defaults.
Session 2 · Harnesses for long-running work
Structure work that spans many context windows: an initial run that sets up the environment, plan, and task list, and later runs that read progress notes, complete one task at a time, and record what changed.
Use durable artifacts as the source of truth between runs, such as progress files, task lists, git commits, and tests, rather than conversation history.
Give the agent feedback loops it can run itself, such as tests, linters, type checks, and end-to-end checks, so it verifies work before marking it done.
Make the environment legible to the agent: short instruction files (such as AGENTS.md), a clear project structure, and documentation written to be read by agents.
Use sub-agents to give focused subtasks a fresh, isolated context and return only condensed results.
Outcome: Design a harness that keeps an agent productive and on track across long tasks that no single context window can hold.

M6.9 · Capstone: Context-Managed Long-Horizon Agent — (sessions: 1)
Take a tool-using agent from Level 5 and run it through a long task where naive context accumulation causes degradation.
Define an explicit context budget and dynamically decide what to keep, retrieve, compress, offload, or discard.
Add history compaction, external state, selective memory retrieval, and tool-output compression.
Wrap the agent in a harness: a progress file and task list it updates, a verification step before any task is marked done, and step and token limits.
Preserve the original goal, constraints, completed work, and pending tasks across a long execution.
Compare the context-managed version against a naive “keep everything” implementation on coherence, token usage, latency, and cost.
Final result: an agent that stays useful across a long, tool-heavy session because its context is actively managed.
Level 6 completion outcome

By the end of this level, you should be able to:

Diagnose context-related failures.
Treat the context window as a finite engineering resource.
Select and prioritize what deserves to enter the window.
Assemble instructions, retrieval, memory, state, and tool outputs effectively.
Compress long histories without losing critical information.
Offload state and working knowledge outside the active context.
Choose between long-context stuffing, retrieval, summarization, and selective loading.
Manage context growth in tool-heavy agents.
Use caching and context reduction to control latency and cost.
Design agent harnesses that keep long-running work on track across many context windows.
Build long-running agents that continuously keep, retrieve, compress, offload, and discard information.
