Level 8 · LLM Evaluations

Scope: Design, execute, and automate comprehensive evaluations for Large Language Models and AI applications to ensure quality, safety, and reliability in production environments.

M8.1 · Introduction to LLM evaluations — (sessions: 1)
Understand the pitfalls of “vibe testing” by examining real-world failure case studies like Air Canada.
Navigate the differences between deterministic software testing and probabilistic LLM systems.
Distinguish between evaluating core foundation model capabilities and testing complete application workflows.
Implement an end-to-end evaluation process covering task definition, criteria, datasets, execution, analysis, and iteration.

Outcome: Understand the foundational need for and workflow of LLM evaluations compared to traditional software testing.

M8.2 · Evaluation methods & paradigms — (sessions: 1)
Categorize evaluation execution mechanisms into Programmatic, Human, and LLM-as-a-Judge approaches.
Understand reference-based vs reference-free evaluation.
Determine when a Golden Dataset answer key is required versus when evaluation can rely entirely on LLM judgment.
Choose the appropriate evaluation method based on whether the target behavior is deterministic, semantic, subjective, or operational.

Outcome: Select the appropriate evaluation execution method and paradigm for a given LLM testing scenario.

M8.3 · Offline vs online evaluations — (sessions: 2)
Use offline evaluation suites for pre-release testing, version comparison, experimentation, and preventing performance regression.
Identify post-deployment production risks including unexpected inputs, emergent systematic failures, changing user behavior, and data drift.
Differentiate automatically captured system metrics such as latency, token usage, and errors from LLM-computed quality metrics such as hallucination or relevance.
Implement a continuous online evaluation pipeline through production logging, sampling, dashboarding, and alerting.
Feed important production failures back into the offline evaluation dataset.

Outcome: Design a dual-layer evaluation strategy that catches regressions before release and monitors quality after deployment.

M8.4 · Model evaluations & benchmarking — (sessions: 1)
Explore core LLM capabilities such as knowledge, reasoning, mathematics, coding, instruction following, long-context understanding, multimodal capability, safety, and tool use.
Analyze the anatomy of a benchmark through its dataset, prompts, run configuration, scoring method, and result aggregation.
Understand how public leaderboards compare foundation models.
Identify benchmark pitfalls including data contamination, score saturation, benchmark overfitting, and configuration gaming.

Outcome: Critically assess public LLM benchmarks and understand how core model capabilities are formally measured.

M8.5 · The evolution of knowledge benchmarks — (sessions: 1)
Trace the progression from benchmarks such as MMLU and TruthfulQA toward harder tests of knowledge and factual reliability.
Understand the use of human exams in benchmarks such as AGIEval to compare human and model capabilities.
Explore harder benchmarks such as GPQA, MMLU-Pro, SimpleQA, and Humanity's Last Exam.
Understand why benchmarks continually become harder as frontier models saturate older datasets.

Outcome: Understand the progression of knowledge benchmarks and select appropriate tests for increasingly capable models.

M8.6 · Custom model evaluations — (sessions: 1)
Move beyond public benchmarks and evaluate models on the actual task your application needs to solve.
Use leaderboards and aggregation platforms to shortlist candidate models based on capability, latency, context, and cost.
Build a custom evaluation dataset for a real task such as Text-to-SQL.
Compare shortlisted models using the same inputs, prompts, parameters, and scoring criteria.
Estimate API usage and token costs and use techniques such as prompt caching where appropriate.
Select the model that offers the best task-specific quality / latency / cost trade-off, rather than simply choosing the highest-ranked general model.

Outcome: Evaluate and select the most capable and cost-effective foundation model for a specific application.

M8.7 · Building an eval suite & regression testing — (sessions: 2)
Structure evaluations across component level, pipeline level, and application level depending on what is being tested.
Maintain versioned test cases, evaluation configurations, prompts, models, and results.
Track experiments and compare new versions against established baselines.
Build automated CI/CD quality gates so changes cannot ship when important metrics regress.
Create a self-improving loop by adding edge cases and failures discovered in production back into the offline golden dataset.
Track quality together with latency and cost so improvements in one area do not silently damage another.

Outcome: Build an automated evaluation suite that prevents regressions and improves continuously from real-world usage.

M8.8 · RAG Evals — (sessions: 5)

Evaluate a RAG system at component, pipeline, application, and safety levels, rather than treating it as one black-box system.

Component-level evaluation
Evaluate the retriever independently to determine whether it finds the information required to answer the question.
Diagnose cases where the retriever completely misses the relevant context or retrieves excessive irrelevant/noisy chunks.
Measure retrieval effectiveness using metrics such as Contextual Recall, Contextual Precision, Recall@k, and other ranking-aware metrics where appropriate.
Generate or curate relevant chunks and ideal answers for a Golden Dataset through hand-authoring, LLM-assisted generation, or tools such as DeepEval's synthetic-data generators.
Evaluate the generator independently by providing known-good context and checking whether it produces faithful and relevant answers.
Detect unfaithful claims, irrelevant answers, missing information, and misuse of provided context.
Implement component tests using frameworks such as DeepEval or RAGAS while understanding what each metric actually measures.
Pipeline-level evaluation
Evaluate the complete retrieval → context → generation pipeline.
Measure the RAG Triad:
Contextual Relevancy
Faithfulness
Answer Relevance
Understand how individually strong components can still interact poorly when connected.
Diagnose cases such as high retrieval precision but low overall contextual relevance or poor downstream answers.
Determine whether the root failure lies in retrieval, assembled context, or generation.
Application-level evaluation
Evaluate the RAG system from the actual user's perspective rather than only testing internal components.
Measure whether the final answer is factually correct given the available evidence.
Evaluate completeness: does the answer address all important parts of the user's request?
Evaluate application-specific requirements such as tone, style, persona, format, citation behavior, and instruction following.
Track operational metrics including latency, token usage, cost per query, and error rates alongside quality.
Safety evaluation for RAG
Evaluate whether the system produces harmful, illegal, dangerous, biased, or otherwise disallowed responses.
Test whether sensitive PII such as contact details, credentials, or payment information is appropriately protected or redacted.
Test direct and indirect prompt injection, including malicious instructions hidden inside retrieved documents.
Test jailbreak attempts intended to bypass application guardrails.
Evaluate whether retrieved malicious or misleading content can manipulate the model into leaking data or ignoring application instructions.

Outcome: Evaluate a RAG application comprehensively across retrieval quality, generator behavior, pipeline interaction, user-facing quality, operational performance, and safety.

M8.9 · Agent Evals — (sessions: 3)

Evaluate agentic systems at the level of decision-making, trajectories, tool usage, task completion, recovery, and safety.

Agent behavior & trajectory evaluation
Understand why evaluating only the final answer is insufficient when an agent autonomously decides how to complete a task.
Evaluate whether the agent chooses the correct tool for a given situation.
Test whether the agent generates accurate and properly formatted tool arguments.
Evaluate the sequence of actions taken by the agent and whether the trajectory is appropriate for the task.
Detect unnecessary tool calls, redundant actions, loops, incorrect ordering, and premature termination.
Measure overall task-completion success rate for complex multi-step user requests.
Failure recovery
Introduce tool failures, malformed results, unavailable services, missing information, and unexpected intermediate states.
Evaluate whether the agent notices failure and chooses an appropriate recovery strategy.
Test whether it can retry, select an alternative tool, revise its plan, or escalate appropriately.
Measure successful recovery rather than only measuring success in ideal conditions.
Agent safety evaluation
Test whether agents attempt unauthorized or destructive actions.
Evaluate human-approval gates and permission boundaries around consequential actions.
Test agent resistance to direct and indirect prompt injections designed to hijack its tool usage.
Attempt to manipulate an agent into revealing secrets, exceeding permissions, or using tools outside the intended scope.
Use relevant cybersecurity benchmarks where appropriate to assess dangerous capabilities such as exploitation, reverse engineering, or other high-risk computer-use behavior.
Track both outcome quality and execution efficiency through steps, latency, tool calls, token usage, and cost.

Outcome: Systematically evaluate whether an agent makes good decisions, uses tools correctly, completes tasks efficiently, recovers from failures, and remains within its security boundaries.

Level 8 completion outcome

By the end of this level, you should be able to:

Design end-to-end evaluation workflows for both offline testing and online production monitoring.
Choose between programmatic, human, reference-based, reference-free, and LLM-as-a-Judge evaluation methods.
Understand and critically interpret public LLM benchmarks.
Build custom model evaluations for specific application tasks.
Create versioned evaluation suites and automated regression testing.
Evaluate RAG systems across retriever, generator, pipeline, application, operational, and safety dimensions.
Measure RAG metrics such as contextual recall, contextual precision, contextual relevance, faithfulness, and answer relevance.
Evaluate agents across tool selection, argument correctness, trajectories, task completion, recovery, efficiency, and safety.
Build production feedback loops that continuously enrich offline evaluation datasets.
Use evaluations as an engineering system for improving AI applications rather than as a one-time benchmark exercise.
