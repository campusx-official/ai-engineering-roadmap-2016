Level 4 · RAG

Scope: build the retrieval layer that RAG depends on — ingestion, chunking, embeddings, vector search, and hybrid retrieval — then ground LLMs in external knowledge, improve retrieval quality, and learn the major RAG architectures used beyond a naive retrieve-and-generate pipeline.

M4.1 · Data ingestion & document processing — (sessions: 2)

Extract content from common sources such as PDFs, HTML, DOCX, and structured documents; understand when OCR is required.
Clean and normalize messy text while preserving useful document structure and metadata.
Handle duplicate documents, document updates, and incremental re-indexing.
Outcome: Convert a real-world document collection into clean, structured data ready for retrieval.

M4.2 · Chunking strategies — (sessions: 2)

Understand why documents must usually be split before embedding and retrieval.
Apply fixed-size, recursive, structural, and semantic chunking.
Reason about chunk size, overlap, boundaries, and metadata and how they affect retrieval quality.
Understand the trade-off between small precise chunks and larger context-rich chunks.
Outcome: Choose a sensible chunking strategy based on document structure and query type.

M4.3 · Embeddings fundamentals — (sessions: 2)

Understand embeddings as vector representations that capture semantic relationships between text.
Generate embeddings for documents and queries using an embedding model.
Understand dimensions, embedding model choice, multilingual/domain performance, cost, and latency trade-offs.
Understand that embeddings from different models/vector spaces generally cannot be mixed directly.
Outcome: Select and use an embedding model appropriate for a retrieval task.

M4.4 · Similarity & semantic search — (sessions: 2)

Understand cosine similarity, dot product, and Euclidean distance and how they are used to compare vectors.
Build a simple semantic-search system from scratch: query → embedding → similarity → top-k results.
Understand the difference between semantic similarity and exact keyword matching.
Explore common failure cases such as exact names, IDs, numbers, and rare terminology.
Outcome: Build semantic search without relying on a vector database and understand exactly what the database will later automate.

M4.5 · Vector databases & ANN search — (sessions: 3)

Store embeddings, documents, IDs, and metadata in a vector database such as pgvector or Qdrant.
Perform top-k vector search with metadata filtering.
Understand why brute-force search becomes expensive at scale and why Approximate Nearest Neighbor (ANN) search exists.
Build intuition for HNSW and IVF and their speed ↔ memory ↔ recall trade-offs without going deep into implementation mathematics.
Understand indexing, updates, deletes, and basic operational considerations.
Outcome: Build and query a scalable vector-search index over a real corpus.

M4.6 · Sparse & hybrid retrieval — (sessions: 2)

Understand traditional lexical retrieval and BM25, and why keyword search can outperform embeddings for some queries.
Compare sparse/BM25 retrieval with dense/vector retrieval.
Combine dense and sparse results using hybrid retrieval and techniques such as Reciprocal Rank Fusion (RRF).
Understand when hybrid retrieval helps, especially for queries containing names, technical terms, IDs, numbers, and exact phrases.
Outcome: Choose between dense, sparse, and hybrid retrieval rather than defaulting to vector search for every problem.

M4.7 · Retrieval evaluation — (sessions: 1)

Create a small set of queries with known relevant documents/chunks.
Understand top-k retrieval and calculate Recall@k.
Compare chunking strategies, embedding models, retrieval methods, and k using the same evaluation set.
Understand why retrieval quality should be measured independently before adding an LLM generator.
Outcome: Evaluate whether a retrieval system actually finds the information users need.

M4.8 · Capstone: Build a Hybrid Search Engine — (sessions: 1)

Ingest and clean a real document corpus, preserve useful metadata, chunk the documents, generate embeddings, and index them in a vector database.
Implement dense search + BM25 + hybrid retrieval, including metadata filters where useful.
Create a small evaluation dataset and compare approaches using Recall@k.
Deploy a simple search API/UI that returns the most relevant chunks for a user query.
Final result: a measurable retrieval system ready to become the retrieval component of a RAG application.

M4.9 · RAG architecture & when to use it — (sessions: 1)

Understand the core pipeline: query → retrieve → assemble context → generate answer.
Understand what RAG solves: private knowledge, frequently changing information, large knowledge bases, and source-grounded answers.
Know when not to use RAG: when the model already knows enough, the task is purely transformational, or the required knowledge can simply fit in context.
Distinguish retrieval failure from generation failure.
Outcome: Decide whether a problem genuinely needs RAG.

M4.10 · Baseline RAG from scratch — (sessions: 2)

Build a complete RAG pipeline manually using the retrieval system built earlier in this level.
Retrieve top-k chunks, assemble them into the prompt, and generate an answer grounded in the retrieved context.
Design prompts that instruct the model to answer from supplied evidence and avoid unsupported claims.
Handle cases where retrieval returns weak, irrelevant, or insufficient context.
Understand the effect of k, chunk ordering, and total context size on answer quality.
Outcome: Build a working RAG application without hiding the mechanics behind a framework.

M4.11 · Reranking — (sessions: 2)

Understand the two-stage pattern: retrieve many candidates → rerank → send the best chunks to the LLM.
Use cross-encoder or dedicated reranking models to reorder retrieved chunks.
Understand why reranking can improve relevance while adding latency and cost.
Compare retrieval with and without reranking and understand when reranking provides little benefit.
Outcome: Improve the quality of context sent to the LLM without simply increasing the number of retrieved chunks.

M4.12 · Query transformation & RAG-Fusion — (sessions: 2)

Understand why the user's original question is not always the best retrieval query.
Apply query rewriting, query expansion, multi-query retrieval, and HyDE.
Understand RAG-Fusion: generate multiple queries, retrieve for each, and combine rankings using techniques such as Reciprocal Rank Fusion.
Use multiple retrieval queries for ambiguous, multi-faceted, or poorly phrased questions.
Understand the trade-off between improved retrieval and additional LLM calls, latency, and cost.
Avoid query transformation when baseline retrieval already performs well.
Outcome: Transform difficult user questions into better retrieval queries.

M4.13 · Grounding, citations & abstention — (sessions: 1)

Generate answers grounded in retrieved evidence rather than unsupported model knowledge.
Attach claims to their supporting documents/chunks and produce useful source citations.
Understand that having citations is not the same as being grounded; the cited source must actually support the claim.
Detect insufficient evidence and respond with an appropriate “I don't know / insufficient information” instead of forcing an answer.
Keep retrieved evidence and model-generated synthesis clearly distinguishable.
Outcome: Produce answers that are traceable to evidence and can abstain when the evidence is insufficient.

M4.14 · RAG variants & advanced patterns — (sessions: 3)

Understand the progression from Naive RAG → Advanced RAG → adaptive/self-correcting RAG architectures.
Learn Self-RAG: retrieval is performed when needed and the model reflects on retrieved evidence and its generated response.
Learn CRAG (Corrective RAG): evaluate retrieved evidence and trigger corrective retrieval when the initial results are weak.
Learn Adaptive RAG: dynamically decide whether retrieval is required and which retrieval strategy should be used.
Understand iterative RAG, where retrieval and generation repeat until enough evidence has been gathered.
Understand multi-hop RAG, where answering requires several retrieval steps or combining evidence from multiple sources.
Learn Graph RAG: represent entities and relationships as a graph and retrieve/summarize information using graph structure rather than relying purely on vector similarity.
Build intuition for when Graph RAG is useful: highly connected knowledge, entity relationships, global questions, and information spread across many documents.
Compare advanced approaches on quality, complexity, latency, cost, and failure mode addressed rather than assuming more advanced RAG is always better.
Outcome: Recognize major RAG variants and choose an architecture based on why baseline RAG is failing.

M4.15 · RAG with frameworks — (sessions: 1)

Rebuild the manually created RAG pipeline using LlamaIndex or LangChain.
Work with framework abstractions for ingestion, indexes, retrievers, rerankers, query engines, and citations.
Implement common RAG improvements such as reranking and query transformation using framework components.
Compare the framework implementation with the hand-built version on control, development speed, debugging, and complexity.
Outcome: Use RAG frameworks productively while still understanding the retrieval and generation mechanics underneath them.
M4.16 · Capstone: Deploy an Advanced RAG Application — (sessions: 1)
Build a document Q&A application over a real corpus with ingestion, chunking, retrieval, generation, citations, and abstention.
Establish a baseline RAG pipeline and add at least one meaningful improvement such as reranking, query transformation, RAG-Fusion, hybrid retrieval, or an advanced RAG variant.
Handle weak retrieval and insufficient evidence gracefully.
Track latency, token usage, and cost across the pipeline.
Deploy the application as an API or simple user interface.
Final result: a complete RAG application that goes substantially beyond a basic retrieve → stuff context → generate demo.

Level 4 completion outcome

By the end of this level, you should be able to:

Convert messy documents into retrieval-ready data.
Choose and tune an appropriate chunking strategy.
Understand and generate embeddings.
Build semantic search from first principles.
Use vector databases and understand ANN search conceptually.
Use metadata filtering effectively.
Understand BM25 and lexical retrieval.
Build dense, sparse, and hybrid retrieval systems.
Measure retrieval quality using Recall@k.
Improve retrieval based on evidence rather than intuition.
Decide when RAG is and is not the right architecture.
Build a complete RAG pipeline from scratch.
Understand how retrieval quality affects generation quality.
Improve retrieved context using reranking.
Improve difficult retrieval queries using rewriting, HyDE, multi-query retrieval, and RAG-Fusion.
Generate grounded answers with citations and appropriate abstention.
Explain and distinguish Naive RAG, Self-RAG, CRAG, Adaptive RAG, iterative RAG, multi-hop RAG, and Graph RAG.
Choose an advanced RAG architecture based on the failure mode of the baseline system.
Use RAG frameworks without treating them as black boxes.
Deploy a production-style RAG application.
